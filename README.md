# 古文単語・文法特訓（完全オフライン）

大学受験向けの古文単語＋古典文法の学習アプリ。サーバー通信・アカウント登録なし。
読み上げは `AVSpeechSynthesizer`（OS標準）のみを使い、音声ファイルを同梱しないことでアプリ容量を極小化している。

公開済みの英単語アプリ（`C:\System_Dev\eitango_app_01`）を土台に、コンテンツ構造を大幅に簡素化した姉妹アプリ。
設計の意図と参考元からの移植方針は `docs/design.md` にある。

## 収録内容

| 種別 | 件数 | 備考 |
| --- | --- | --- |
| 古文単語 | 314語 | 見出し語（歴史的仮名遣い）・読み・意味・品詞・例文・訳・出典 |
| 文法項目 | 80項目 | 助動詞28 / 助詞20 / 敬語16 / 識別・その他16 |
| 文法問題 | 125問 | 4択。誤選択肢まで手書きで用意（自動生成しない） |

階層・分野・頻出度といった分類は持たない。属性は品詞だけで、一覧はすべて五十音順（単語）か文法書の慣例順（文法）。

## 画面構成

タブは **ホーム / 単語帳 / 4択クイズ / 聞き流し** の4つ。文法は単語帳タブ内のセグメントで切り替える。

- **ホーム** — 連続学習日数と直近1週間のグラフ、単語・文法それぞれの習熟度、復習の件数、学習開始の導線
- **単語帳** — 単語一覧（検索・習熟度で絞り込み）と文法一覧（カテゴリ別）。詳細から読み上げ・「覚えた」「やり直す」操作
- **4択クイズ** — 単語クイズ（選択肢は自動生成）と文法クイズ（同梱の問題バンク）。1回10問・1問20秒
- **聞き流し** — 読み→意味（設定で例文と訳も）を連続再生。バックグラウンド・画面オフでも継続

## ビルド方法（Mac実機なし・GitHub ActionsのmacOSランナーを使用）

`.xcodeproj` はコミットせず、[XcodeGen](https://github.com/yonaskolb/XcodeGen) が `project.yml` から毎回生成する。

- **ビルドとテスト**: push すると `.github/workflows/ios-build.yml` が走る。同梱データの検証（ubuntu）→ シミュレータでのビルドとテスト（macOS）の2段構成
- **画面の確認**: 同じワークフロー内で `KobunAppUITests` がシミュレータ上でアプリを操作し、主要画面を [`xcparse`](https://github.com/ChargePoint/xcparse) でPNG抽出する。Actionsの実行結果 → Artifacts欄の **`ui-screenshots`**
- **TestFlight配信**: Actionsタブ → **TestFlight** ワークフローを手動実行。push のたびに配信するとビルドが溜まりテスターへの通知も続くため、意図的に手動トリガーにしている

証明書とProvisioning Profileは持ち回らず、App Store Connect APIキーを使って `-allowProvisioningUpdates` でXcodeに取得させる。必要なSecretsは `ASC_API_KEY_ID` / `ASC_API_ISSUER_ID` / `ASC_API_KEY_P8` の3つ。

Macがある場合のローカル手順:

```bash
brew install xcodegen
xcodegen generate
open KobunApp.xcodeproj
```

## 学習データの編集

正本は `data/` の3ファイル。編集したら必ず生成スクリプトを走らせ、出力もコミットする。

```bash
python scripts/build_seed.py            # 検証して KobunApp/Resources/kobun_seed.json を生成
python scripts/build_seed.py --check    # 検証のみ（CIが実行する）
```

スクリプトが弾くもの: ID重複 / 必須項目の欠落 / 未知の品詞・カテゴリ / `sortOrder` の重複 /
選択肢が4件でない・重複している / `answerIndex` が範囲外 / 参照先の無い `grammarKey`。

`build_seed.py` は出力の `version` を自動で1つ上げる。アプリは「同梱の version が適用済みより新しいとき」だけ
データを取り込むため、内容を変えたのに version が据え置かれると変更が端末に届かない。
CIは `data/` と同梱JSONの内容が一致しているかも検証する（生成し忘れの検出）。

### IDの扱い

`KOBUN_W_*` / `KOBUN_G_*` / `KOBUN_GQ_*` は学習履歴のキーでもある。

- **公開後の改名は禁止**。改名は「削除＋新規」になり、その項目の学習履歴が全ユーザーで失われる
- 削除はしてよい（シーダーが孤児進捗を許容する設計）。意味・例文・解説の修正も自由

## データベース設計の要点

- マスター（`WordMaster` / `GrammarMaster` / `GrammarQuizItem`）と学習履歴（`ItemProgress`）は
  String の ID でのみ緩く結びつけ、SwiftDataの `@Relationship` は張らない。
  「マスターは総入れ替え、学習履歴は絶対保持」という要件のため、意図的に疎結合にしている
- アプリ更新時、同梱 `kobun_seed.json` の `version` が既適用より新しければ `KobunSeeder` がUpsertする。
  `ItemProgress` には一切触れないため、データを総入れ替えしても進捗は保持される
- 進捗の行は最初に解答した時点で作る。全項目ぶんの空行を先に作ると初回起動と集計が重くなる

### 起動時の堅牢性

データが入らなくてもアプリが「起動しない」状態にはならないようにしている。

- 適用済みバージョンは UserDefaults、実データは SwiftData と保存先が分かれるため両者は食い違いうる。
  データが0件ならバージョンに関わらず再シードする
- バージョンの記録は `context.save()` が成功した**後**。逆順にすると save 失敗時に
  「バージョンだけ進んでデータが空」の状態が永続化され、以降のシードがスキップされて復旧できなくなる
- シード失敗は `AppContainer` でログに記録するだけで起動は継続する
- 永続ストアを開けない場合はインメモリにフォールバックする

## 間隔反復（SRS）について

出題順は `Services/Study/StudyQueue.swift` が決める。ランダムではなく次の優先度で並べる。

1. 復習期限が来た項目 2. まだ一度も解いていない項目 3. 期限前の項目（期限が近い順）

間隔は Leitner ボックス方式の固定テーブル（0/1/3/7/14/30日）。正解で1段階上がり、不正解で段階0に戻る。
次回復習日は「日」単位に丸めるので、朝に解いても夜に解いても期限は同じ日付になる。

**文法の進捗は問題単位**で持つ。文法項目そのものの習熟度は、紐づく問題群から `GrammarMastery` が導出する
（1問でも要復習があれば要復習、全問が覚えた段階のときだけ覚えた）。解ける問題が残っているうちに
「覚えた」と表示しないための決め方。

## 読み上げについて

`WordMaster` は見出し語（`word`、歴史的仮名遣い）と読み（`reading`、現代仮名遣い）を別々に持つ。

- 画面表示は `word`、**TTSに渡すのは必ず `reading`**。「あはれなり」をそのまま読ませると綴り字どおりに誤読される
- 五十音順のソートと検索も `reading` を使う（歴史的仮名遣いで並べると辞書の並びとずれる）

1語だけ読む `WordPronouncer` と、連続再生の `AudioPlaybackManager` は別物。前者は `.mixWithOthers` で
控えめに割り込み、後者はオーディオセッションを占有する。混ぜるとクイズのBGMが読み上げのたびに止まる。

## 課金と試用について

無料で配布し、買い切りのApp内課金で全項目を出題対象に加える。**広告とサブスクリプションは実装しない。**

初回起動から14日間は全項目を試せる。**期間が終わってもクイズ・聞き流しは使えるまま**で、
変わるのは出題対象が無料範囲（単語147語・文法問題54問）に狭まることだけ。
単語帳と文法解説の閲覧・検索・読み上げは常にすべてできる。
一定期間後に動かなくなる体験版は App Review の拒否対象であり、教育カテゴリでは
「使えなくなった」という★1レビューを最も招くため、機能を止める作りにしていない。

試用を14日にしているのは習熟度の設計に合わせている。「覚えた」は7日間隔の復習に正解して初めて付き
（最短で4日目）、その復習が実際に戻ってくるのは11日目になる。7日で切ると
「間隔をあけても思い出せた」という核心を体験する前に購入判断を迫ることになる。

| 型 | 役割 |
| --- | --- |
| `AccessRights` | 権利から出題可否を決める値型。StoreKitにもUserDefaultsにも触れないのでそのままテストできる |
| `TrialManager` | 試用の起点をUserDefaultsに記録する。時計を戻して延長されないよう、観測済みの最新日時で判定する |
| `Entitlements` | StoreKitと試用をまとめ、画面に「いま何が出題できるか」を答える |

`Transaction.updates` を購読して払い戻しを反映している。これを見ないと返金後も解放されたままになる。

## テスト方針

「壊れても画面上は正常に見え、学習効果だけが静かに落ちる」ロジックを優先的に検証している。

| テスト | 対象 |
| --- | --- |
| `SpacedRepetitionTests` | Leitnerボックスの進退・復習日の丸め・「覚えた」の条件 |
| `StudyQueueTests` | 出題順の優先度・復習件数と実際の出題数の一致 |
| `GrammarMasteryTests` | 文法項目の習熟度の集約規則 |
| `QuizChoiceBuilderTests` | 選択肢の重複排除・正解位置の整合・候補不足時の縮退 |
| `StudyHistoryTests` | 欠損日の0埋め・連続日数・解答数で重み付けした正答率 |
| `AccessRightsTests` | 無料/有料の線引き・試用期間・時計の巻き戻し対策 |
| `SeedDataTests` | 実際に同梱されるJSONの整合（ID重複・参照切れ・選択肢の形・無料範囲の分量） |

## 実装しないもの

- 広告
- サブスクリプション課金
- サーバー通信（購入・復元時のApple標準の通信を除く）
- タイピング機能（参考元にはあるが、古文の学習に対応する行為が無いため）
- ユーザーによる単語の追加
